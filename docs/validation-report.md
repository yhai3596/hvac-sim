# 仿真验证报告 v2

运行方式：`python3 -m sim.run_validation`（数据表生成到 [`validation-tables.md`](validation-tables.md)）；单元测试 `python3 -m sim.test_sim`（14 项通过）。JS 前端与 Python 核心为同一模型的双实现，交叉验证逐项一致（迈阿密设计日 B 算法 3 天：达温 543 min、t2 59.74、间隔 75.13、到峰值 15.07 min、38.04 kWh、RH 61.4%、除湿 70.0 L/天，两端完全相同）。

本版围绕两项客户反馈组织验证：**达温慢（舒适度）** 与 **除湿能力不足**。

## 1. 主要结论（针对客户反馈）

### 达温慢的归因排序（V4 分解实验）

| 贡献项 | 量级 | 证据 |
| --- | --- | --- |
| ① 容量配比 | **支配项** | 设计日（配比 0.97）阶跃达温 ~8h，所有算法/爬坡方案差异 <5%；典型日（有裕度）降到 ~6h |
| ② V1.44 算法行为 | 典型日 **+9~10%** | 4b：C 407 min vs B 371 min；DOWN 信号压制 pull-down 能力 |
| ③ 压缩机爬坡保守 | 小（1~2 min/循环起步段） | 快爬升（1.5Hz/s、保持 60s）仅缩短达温 ~2 min，但"压缩机到峰值时间"从 6.9→4.5 min |
| ④ 温控器特性 | 影响循环统计而非达温本身 | 回差 0.5→2°F 循环次数 40→14.7 次/天（前版 S5b） |

**结论：客户"达温慢"投诉优先排查容量配比（房屋负荷 vs 机型选型），其次是 V1.44 未区分 pull-down 与稳态循环（改进点：识别 pull-down 事件时暂停 DOWN 信号/临时满能力）。压缩机爬坡参数不是主因，但"到峰值时间"指标可作为交付验收项。**

### 除湿不足的归因排序（V1/V2/V3）

| 贡献项 | 量级（迈阿密/休斯顿设计日） | 机理 |
| --- | --- | --- |
| ① Tes 高度 | Tes 5→13℃：RH 均值 60.9→65.6%、RH>60% 时间 58%→86%、除湿 71.6→57 L/天（同时省电 28%） | 变频机 PI 把 Te 钉在 Tes → **SHR 由 Tes 直接决定**；V1.44 往上学 Tes 时除湿是它看不见的代价（外机无湿度传感） |
| ② 容量配比过大 | 配比 0.83→1.64：RH>60% 时间 52%→76% | 短循环 → 盘管湿润时间占比低 + 停机再蒸发（风机延迟/常开把盘管存水吹回房间） |
| ③ 风量匹配 | 330→450 CFM/ton：RH 均值 57.7→59.1%（定频机上差异更大） | 变频+定 Te 控制下风量的除湿差异大部分被 Te 控制吸收——这是仿真发现的重要洞察 |

**结论：除湿不足首先是"节能（Tes↑）↔ 除湿（Tes↓）"的物理矛盾——V1.44 的节能收益中约有一半以除湿损失为代价（每抬高 1℃ Tes ≈ 省电 3.5% / RH +0.6pp / 除湿 −1.8 L/天，迈阿密设计日量级）。改进方向明确：湿区机型给 Tes 上限设"湿度墙"（如按气候区配置 Tes_max，或热湿联控：检测长循环高潜热特征时收紧 Tes 上限），并避免超配选型。**

## 2. 其余验证要点

- **V0 地点设计负荷**：8 城市配比一览。同一台 7 kW 机：洛杉矶过配 2.15、佛州/德州 0.9~1.1、波士顿制冷 1.38 但**制热仅 0.62**——寒区一拖一按制冷选型必然制热不足。
- **V5 制热**：波士顿设计日（−13.9℃）热泵能力衰减到 ~3.9 kW，8 kW 辅热仍不足，连续运转（真实现象：寒区需双燃料或更大辅热）；此时无循环，V1.44 学习完全失效。休斯顿典型冬日则正常循环，**V1.44 Tcs 学习生效：循环从 71 次/天（定频）压到 25 次/天，达温间隔 58 min ≈ TA 目标 60 min**，Tcs 学到 38~41℃。代价同样是出带时间 1.4%→19.7%。
- **V6 保温档**：达拉斯老房（UA 520，配比 0.63）设计日达温 824 min、RMSE 2.65℃——保温差的房子上任何算法都救不了容量缺口；升级保温使耗电 −31%。
- **V7 TA 扫描 + 预学习敏感性**：标定负荷下 TA 30→90 有预期方向的响应；**对照行显示预学习值偏高 36% 会导致目标总负荷高估 → 持续 UP → Tes 锁死下限、节能功能整体失效**——负荷初值/测量偏差的鲁棒性是 V1.44 的真实薄弱点（对应分析文档缺点 2.2-3/2.2-5）。
- **V8 冷启动**：休斯顿典型夏周 7 天仅学成 2 个箱组合（缺点 2.2-1 复现）。

## 3. 模型边界与可信度

1. 单区集总模型 + 一阶设备曲线：用于**参数相对比较与趋势排序**；绝对值（尤其 RH%）需一次实验室标定锚定；
2. 气候设计值为内置 ASHRAE 参数（`sim/climate.py` 顶部有来源与复核说明；本环境网络被策略限制无法访问 ashrae-meteo.info，发布前请对照复核）；
3. ADP/旁通因子模型的已知特性：变频定 Te 控制下 SHR 与风量近乎解耦（Te 被控制钉住），风量的除湿效应主要体现在定频机与容量受限（频率顶格）工况；
4. 制热"压缩机进入 PI"采样起点近似为启动 3 min（与制冷同）；化霜期能力计 0 与 PPT 一致。

## 4. 使用平台复现

```bash
python3 -m sim.test_sim          # 14 项单元测试
python3 -m sim.run_validation    # V0~V8 全场景，重新生成数据表
```

```python
from sim.scenarios import run_scenario, run_setpoint_step

# 例：迈阿密，V1.44 预学习，改 TA 与风量
r = run_scenario("C", "miami", days=3.0, prelearn_q=5000, ta_min=45,
                 cfm_per_ton=350, deadband_f=1.0)
print(r.summary())

# 例：设定阶跃 pull-down 对比
r = run_setpoint_step("C", "fresno", scenario="summer_typical", prelearn_q=3800)
```

# 现有空调控制算法分析（北美替代市场・内外机无通讯场景）

> 输入材料：
> - 《空调控制算法 PPT（V1.44）》——现有算法，本文分析与改进的对象（负荷预测 + Tes/Tcs 自学习）
> - 《CC 算法与 FDD 协同应用技术方案 V1.0》——参考架构（健康/能耗观测、门控与融合决策思想）
>
> 场景约束（项目事实）：北美以替代市场为主，外机与内机**无通讯**。外机对内机需求的感知只有两条途径：
> 1. **冷媒状态**（Te/Tc 或高低压、吸气/排气温度、过热度等外机自测参数）；
> 2. **温控器达温停机**（thermostat 达温断开 Y 信号 → thermo-off；超温闭合 → thermo-on），
>    表现为外机可观测的开停时序 t1（停机时长）/ t2（运转时长）。

---

## 1. 现有算法（V1.44）逻辑解读

### 1.1 总体思路

现有算法的核心是：**用 thermo-on/off 的开停时序 + 外机冷媒侧测得的输出能力，反推房间热负荷；再以"目标运转时间"为控制目标，自学习目标蒸发温度 Tes（制热为目标冷凝温度 Tcs），让每个运转循环拉长到约 60 分钟，从而减少压缩机启停次数。**

信息流：

```
thermo-on/off 时序 (t1, t2)          外机冷媒侧能力测量 (Gr×Δh 积分)
        │                                    │
        └────────────┬───────────────────────┘
                     ▼
       负荷系数 q 自学习（按室外温度区间 × 昼/夜 分箱）
                     ▼
       目标总负荷 =  t1 段负荷 + 目标运转段负荷 (TA=60min)
                     ▼
       运转中每 20s：预测总能力（当前能力恒定外推）
                     ▼
       预测总能力 / 目标总负荷 → 能力 UP/DOWN 信号（带滞环）
                     ▼
       调整 Tes（分区间保存）→ 改变压缩机输出能力
```

### 1.2 关键机制明细

| 机制 | 内容 | 备注 |
| --- | --- | --- |
| 循环定义 | 从停机到下一次停机为一个循环；t1 = 停机→压缩机再启动 [1, 300min]，t2 = 运转→停机 [1, 300min]，t0 = t1 + t2 | 完全由 thermo 信号驱动 |
| 负荷分箱 | 制冷按室外温度 16 个区间（约 3℃ 一档，覆盖 0~46℃），制热覆盖 -20~22℃；每箱再分白天 [7:00,19:00) / 夜 [19:00,7:00) | 隐式吸收日照影响 |
| 无效循环判据 | LP/HP 应急运转；t1<5min 或 t1≥120min；t2<5min 或 t2≥240min → 该循环不入样本 | 防污染，但也丢工况（见 2.2-8） |
| 负荷系数学习 | 7 天采样（每天 1~6 点，7 天累计 7~42 点）；中心值法（min Σ\|差分\|）选中心 → 70% 信赖区间内取平均得 q；信赖区间上下限 = (极值−q)×120%+q | 稳健统计，抗离群 |
| 新样本处理 | 新数据落在信赖区间内 → 替换距中心最远的旧数据并重算；区间外 → 丢弃 | 稳但滞后（见 2.2-5） |
| 能力测量 | 压缩机启动 3min 后（制热为进入 PI 或 Tc≥Tcs−2）开始，每 20s 采样冷媒质量流量 Gr × 焓差 Δh 积分得循环总能力；q = 总能力×20s/t0 | 无流量计，Gr 依赖压缩机 map（见 2.2-3） |
| 目标负荷 | STEP1 停机段 t1 各温度区间加权负荷（t1>120min 时只取最近 120min）；STEP2 运转段负荷 = q×TA×60；STEP3 目标总负荷 = 两者之和 | TA = 60min（可设定） |
| 能力预测 | 运转中每 20s：已积累能力 + 当前能力恒定外推至 TA；超时则 TA+10min 逐次延长，超过 240min 作废 | "能力恒定"假设（见 2.2-9） |
| UP/DOWN 判定 | 预测/目标 ≥120% → 能力 DOWN=ON；回落 <110% → OFF；≤80% → 能力 UP=ON；回升 >90% → OFF；90~110% 无动作 | ±20% 死区 + 10% 滞环 |
| Tes 保存 | 进入目标时刻 ts 所在温度区间保存学得的 Tes | 分箱记忆 |
| 学习前提 | 区间负荷系数未学成 → 不发 UP/DOWN 信号（不优化） | 冷启动期无收益（见 2.2-1） |

### 1.3 它在无通讯约束下解决了什么

在内外机无通讯时，外机**不知道室温、不知道设定温度、不知道温控器回差**，只能看到"内机要冷/不要冷"。V1.44 的价值在于：

- 把 **t1（停机时长）当作房间升温速度的代理**，把 **t2（运转时长）当作出力/负荷匹配度的代理**；
- 用外机自己能测的 **冷媒侧能力积分**给"负荷"标定出物理量纲（kW）；
- 学到的负荷系数是"这栋房子 + 这台内机 + 这个温控器"的**个体化综合参数**，不需要知道其中任何一项的细节。

这与 CC 文档 5.1 节的需求代理思想（D = t_on/(t_on+t_off)）同源，但 V1.44 走得更远：它不但用时序做相对判断，还试图标定绝对负荷（kW）并用于前馈式的能力规划。

## 2. 优缺点分析

### 2.1 优点

1. **完全贴合无通讯硬件约束。** 仅依赖 thermo 时序 + 外机自测冷媒参数，不要求内机任何数据，天然适配替代市场（内机/温控器品牌不可控）。
2. **负荷自学习、免现场调试。** 按外温分箱 × 昼夜分层，隐式吸收房屋 UA、蓄热、日照、内扰的综合影响；不需要人工输入房屋参数。
3. **稳健统计设计。** 中心值法 + 70% 信赖区间 + 区间外丢弃，对用户偶发扰动（开窗、来客）和测量毛刺有较强的抑制能力；无效循环判据把化霜、保护、极端循环挡在样本外。
4. **直击替代市场痛点——启停次数。** 北美被替代对象多为单级 on/off 机组，短循环（short-cycling）是能耗与寿命双输。以"目标运转时间 60min"为目标把循环拉长，减少启停损耗、降低压缩机磨损，也改善除湿（运转段长有利于除湿）。
5. **控制信号带死区 + 滞环（120/110、80/90）**，避免能力信号抖动导致 Tes 频繁变化，工程上稳妥。
6. **计算量小、可嵌入。** 分箱查表 + 一阶外推，单片机级即可实现，无需云端。
7. **Tes 直接对应节能量。** 蒸发温度每提高 1℃，COP 约提升 2~3%（行业共识），在负荷允许时抬高 Tes 是变频机部分负荷节能的正路（与 CC 文档引用的变蒸发温度控制文献方向一致）。

### 2.2 缺点与风险

1. **冷启动期长、无优化兜底。** 每个温度分箱要凑满 7 点（最多 7 天、缺工况时更久）才生效；学成前不发 UP/DOWN 信号，设备退化为固定策略。换季（跨箱）、搬家、改造后都要重学。
2. **收敛慢、调整粒度粗。** 学习以"循环"为节拍，一天只有十几个有效循环；TA=60min、±20% 死区、3℃ 箱宽均为固定参数，没有依据收敛情况自适应。
3. **能力测量（Gr×Δh）系统误差直接进入负荷标定。** 无质量流量计，Gr 来自压缩机 map（频率/压比），对冷媒充注偏差、换热器脏堵、压缩机磨损敏感。**设备一旦衰减，"测得能力"与真实能力脱钩，负荷系数被带偏——算法无法区分"负荷变大"与"能力变差"**。这正是 CC 文档要补的核心缺口（其 6.3 节"防止把衰减学成正常"）。
4. **温控器回差不可知且跨品牌差异大。** 北美温控器回差 0.5~2°F 不等，且智能温控器（Nest/Ecobee 类）带预测/anticipation 逻辑，t1/t2 与真实负荷的映射被回差幅值和策略缩放。同一负荷下，回差大→循环长、回差小→循环短，学到的 q 是"负荷×回差特性"的耦合量，跨温控器不可迁移（CC 文档 5.2 的"关键限制"同此判断）。
5. **对负荷真实突变适应慢，且置信区间会"锁死旧现实"。** 新样本只有落在旧信赖区间内才被接纳；季节过渡、用户长期改变作息时，新工况数据恰恰落在区间外被丢弃，q 需要很长时间才能跟上。防污染机制与快适应互为代价，当前设计偏保守。
6. **达温时间与停机时间此消彼长，算法未区分场景。** 能力 DOWN 把 t2 拉向 60min 省启停，但用户**改设定后的 pull-down（初始达温）也被同样压慢**——thermo-on 后迟迟不达温，直接体感是"新机器不给力"。V1.44 没有 pull-down 事件识别（如 thermo-on 且 t1 异常短/长、连续运转超时）与稳态循环的区别处理，只有"超时 TA+10min 延长"这种被动兜底。
7. **昼/夜 7:00/19:00 硬二分。** 早晚过渡时段日照差异大，同箱内湿度差异也未建模（潜热负荷在北美湿区不可忽略），q 的箱内方差偏大。
8. **t1≥120min 或 t2≥240min 一律丢弃。** 春秋轻负荷季循环天然极长，恰是变 Te 节能收益最大的工况，反而学不到；深冬/盛夏连续运转（t2 长）同样被丢。
9. **"当前能力恒定"外推假设的系统偏差。** 变频机在循环内降频、化霜、保护限频时能力单调变化，恒定外推会高估/低估预测总能力，导致 UP/DOWN 误发；滞环只能部分吸收。
10. **无健康/数据可信度门控。** 采样有效性只看保护标志与时长窗口；冷媒泄漏、脏堵渐变时样本照常入库，Tes 学习在"带病基准"上运行。CC 文档的 data_confidence、基准冻结、FDD 排他等机制在 V1.44 中缺位。
11. **thermo-off ≠ 达温。** 内机自身保护（防冻结停风）、风机故障、温控器断电等也表现为需求消失；外机侧无法区分，会当作"满足快"误学习。
12. **分箱单值记忆、无置信度输出。** 每箱只存一个 Tes，不带样本量/方差信息，下游无法按可信度降级使用。

### 2.3 与 CC 参考方案的互补关系

CC 文档不替代 V1.44 的能需控制（其 9.1 节明确保留开停周期判断需求的原有逻辑），它补的是 V1.44 最薄弱的三环：

| V1.44 缺口 | CC 方案对应机制 |
| --- | --- |
| 无法区分负荷变化与能力衰减（2.2-3、2.2-10） | 工况归一化基准 + 标准化残差 + FDD 排他诊断 |
| 带病学习（2.2-5、2.2-10） | 基准更新门控、异常时冻结、RECOVERY 状态机 |
| 无可信度概念（2.2-12） | data_confidence 门控：低可信只展示不闭环 |
| 激进节能的安全边界（2.2-6） | 控制许可 permission + Te 修正限幅/斜率/保持时间 |

**结论：改进方向不是推翻 V1.44，而是（a）解决冷启动与收敛速度，（b）把 pull-down 与稳态循环分开对待，（c）引入 CC 式的门控与可信度，（d）让 TA/死区等固定参数可评估、可调优。** 这正是需要仿真平台的原因：这些参数在真机上试错成本极高（一个循环 1 小时、一轮学习 7 天）。

## 3. 仿真平台要回答的问题

1. 给定房屋/气候/温控器特性，V1.44 相对"定频 on/off 基线"和"变频固定 Tes"在**达温时间、停机时间、循环次数、能耗**上的量化差异；
2. TA（目标运转时间）、±20% 死区、Tes 步长/上下限等参数扫描下的指标敏感度；
3. 温控器回差、能力测量偏差（模拟 Gr×Δh 误差）对学习质量的影响；
4. 7 天学习期的收敛过程可视化；设定温度阶跃（pull-down 场景）下的行为对比。

仿真模型设计见 `docs/simulation-plan.md`，验证结果见 `docs/validation-report.md`。
